## V0.2 执行规划（待完成）

V0.2 的目标是：**把这 10 张任务，用同一套 Prompt 骨架，交给不同的模型真刀真枪跑一遍，然后按 `scoring.md` 打分，把成绩填到下面的表里。**

具体步骤（规划，V0.1 未执行）：

### Step 1：确定参赛模型清单（V0.2 时确定）

候选池（仅举例，最终以 V0.2 决策为准）：

- GPT 系列（GPT-4o / GPT-4o mini / o1 等）
- Claude 系列（Sonnet / Opus / Haiku 等）
- 国产模型（DeepSeek / 通义 / 豆包 / Kimi / 文心 等）
- 开源模型自托管（Llama 3 / Qwen 2 等）
- 对照组：人类工程师（1~3 名小白 + 1 名熟手）

### Step 2：统一 Prompt 骨架

为每个任务 `tasks/BXX-*.md` 生成一份**固定的 Prompt 模板**，内容包括：

- 任务 Goal / Input / Expected Behavior 原文（从 BXX 文件里直接引用）；
- 项目骨架文件内容（原样注入）；
- 明确的输出要求（"先想再答 / 代码放哪 / 测试在哪 / 哪些文件要新建或修改"）；
- 明确禁止项（"不要伪造 API Key / 不要用硬编码绕过 / 不要省略输入校验"）。

确保每个模型收到的 Prompt **除模型适配的格式差异外，语义完全一致**。

### Step 3：统一运行环境

- 统一 Docker / Node 版本（暂定 Node 20 LTS）；
- 统一 SQLite / Redis / npm 镜像源；
- 统一超时与重试策略（默认单任务 ≤ 30 分钟，最多重试 2 次）；
- 记录每个任务实际消耗的 **Token** 与 **Wall-clock Latency**，填入 scoring 的第 6、7 维。

### Step 4：自动化验收

- 对每个任务的 Acceptance Criteria，写一个可重复执行的验收脚本（优先 Node 原生 + `node:test` 或 `vitest`）；
- 脚本运行产出结构化 JSON（每项 AC 的 pass/fail 与耗时）；
- 脚本再按任务的 `Evaluation` 节把 AC 映射到 8 个维度分，最后调用 scoring.md 的加权公式得到总分。

### Step 5：人工复核（Human Intervention 维度）

- 记录 AI 产出过程中人类"纠偏 / 手修 / 重跑"的次数；
- 对 Code Quality / Maintainability 维度做一次双人盲审打分，取均值；
- Security 维度同时跑静态扫描工具（如 eslint-plugin-security / npm audit）+ 人工复核，取两者最低分。

### Step 6：结果落盘

- 每个模型生成 `results/{model_name}/BXX.md` 详细报告（8 维分 + 每项 AC 截图/日志 + 产物代码链接）；
- 在本页下方的「模型对比总表」里填入每模型每任务的总分；
- 再加一张「按维度聚合的雷达图」（文字版或嵌入 Mermaid，V0.2 实现）。
