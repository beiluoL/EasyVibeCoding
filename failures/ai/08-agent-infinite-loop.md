# Agent 无限循环

## Problem

搭了一个 **Agent（智能体：能自己规划步骤、调用工具、反复思考直到完成任务的 AI 程序，首次出现，配大白话：会自己想下一步干啥的 AI 小机器人）**，想让它自动完成"调研 → 写代码 → 自测"。结果它一直在"重新规划 → 看一下文件 → 又重新规划 → 又看一下文件"的死循环里转，跑了半小时、烧了几十块钱，最后啥也没产出，还得你手动 kill。

## Context

典型场景（示意）：用 LangChain / AutoGen 之类的框架写了个 ReAct Agent，工具给了"读文件 / 写文件 / 搜索网页 / 跑命令"。prompt 里写的是"帮我把 Todo 应用从 Express 迁移到 NestJS"，然后就放它跑。Agent 读了 5 个文件，写了一份迁移计划，然后觉得"计划还不够详细"，又读了一遍同样的 5 个文件，再写一份差不多的计划；接着又怀疑自己漏看了某个路由，再读一遍……循环往复，步数已经 40 多步了，还在"规划"阶段，一点实际修改都没做。

## Expected

Agent 在合理步数内（比如 15~25 步）完成"读 → 规划 → 修改 → 验证"的闭环，**明确宣布完成**并给你改动摘要。

## Actual

Agent 陷入"再规划"循环：

- 反复读取相同文件，反复输出结构类似但略改的计划。
- 一直在"思考（Think）"和"观察（Observe）"，几乎不进入"行动（Act）"。
- 步数飙升，token 狂烧，没有产出。
- 没有任何机制主动停止，只能开发者发现异常后手动终止。

## Root Cause

没有给 Agent 设定**强制终止条件**和**步数上限**。Agent 是个"总想把事做完美"的完美主义者，只要你不叫停、不设边界，它就会认为"我还可以再优化一下计划"，永远不会觉得"够了，可以动手了"。

常见缺失项：

1. 没有 `max_steps`（最大步数）硬上限。
2. 没有"任务完成判定"的明确标准（什么叫"做完了"）。
3. 没有 token/费用的预算上限。
4. Prompt 里没告诉 Agent：**当重复≥2 次类似动作时，必须停止并上报**。

## Why AI Failed

- Agent 的循环没有"默认刹车"。框架默认你会自己设 `max_steps`，但小白容易忘，AI 自己不会"觉得够了"。
- Agent 的 LLM 每一轮都是独立决策的。它不记得"这已经是我第 5 次读同一个文件了"，除非你在 prompt 或代码里明确提醒它。
- 人类开发者也容易犯"等一等说不定就好了"的心理，没有及时介入。

## Fix

1. **硬加 `max_steps`**：代码层强制设上限（比如 20~30 步），超过直接抛出 `MaxStepsExceededError` 并把当前进度保存下来让人接手。
2. **加终止判定（finish condition）**：
   - 在 prompt 里明确写："当你修改了所有必要文件、跑过验证命令、且没有未解决错误时，调用 `finish` 工具并输出改动摘要；**严禁继续优化**。"
   - 给"完成"列一个 checklist（如：代码改完了？测试过了？有 README 吗？）。
3. **加循环检测**：代码里判断"连续 N 步（如 3 步）做了相同或等价动作（读同一文件、输出几乎一样的计划）"，触发则自动终止并报错。
4. **加预算上限**：在 Agent 外层套一个 token/费用计数器，超过阈值（比如 2 美元）立刻停。
5. **加"遇到卡点就停下来问人"的逻辑**：prompt 里加："同一问题尝试 2 次还没解决，停止并向用户提问求助，不要死磕。"

## Prevention

- 写 [build-agent 提示词](../../prompts/ai-app/build-agent.md) 时，**终止条件必须占单独一节**，和"工具列表"、"任务描述"同等重要，永远不要省略。
- 所有 Agent 必须带两个安全开关：**步数上限 + 预算上限**，缺一不可。
- 给 Agent 列权限边界：哪些工具可以随时用、哪些要确认、哪些不给。避免它在"权限不够→想绕→权限还是不够→继续绕"的循环里烧钱。
- 第一次跑 Agent **一定盯着看**，别放后台跑一夜。前 10 步就能看出会不会循环。
