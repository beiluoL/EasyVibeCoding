# Requirements — RAG 问答应用

> ⚠️ Verification Pending — 需求清单已就位，但功能尚未实际实现验证。

## 功能性需求（FR）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 用户能上传/指定一份本地文档（PDF/MD） | P0 | 给定路径能加载并显示文档已入库 |
| FR-02 | 用户能针对文档内容提问并得到回答 | P0 | 问文档内问题，回答正确且引用出处 |
| FR-03 | 回答必须标注引用来源（文件名+片段号） | P0 | 每条回答附出处，可回查原文对应片段 |
| FR-04 | 用户能连续多轮提问，保持上下文 | P1 | 追问能引用前文，不必每次重述背景 |

## 非功能性需求（NFR）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| NFR-01 | 单次问答检索延迟目标 < 3 秒（本地） | P1 | ⚠️ 未实测，为目标值 |
| NFR-02 | 文档内问题准确率目标 ≥ 80% | P1 | ⚠️ 未实测，需用已知答案集测 |
| NFR-03 | 文档外问题应明确答"未覆盖"而非编造 | P0 | 问文档外问题，回答含"文档未提及" |
| NFR-04 | API Key 不入库，从环境变量读 | P0 | 全仓库 grep 不到真实 key |
| NFR-05 | 上下文不超 LLM 窗口（截断或择优） | P1 | 检索片段总长不超模型上限 |

> ⚠️ NFR-01 / NFR-02 为目标值，尚未实测。检索延迟与准确率需用真实问题集回归后才能得出。

## 验收标准（Acceptance Criteria）

端到端验收（全部通过才算交付）：

1. ✅ 给定一份 PDF/MD，能加载切块向量化入库
2. ✅ 问一个文档内有答案的问题，回答正确且引用对应原文
3. ✅ 问一个文档外的问题，回答明确说"文档未覆盖"
4. ✅ 引用出处可在原文中找到对应片段
5. ✅ 连续追问，能引用前文不丢失上下文
6. ✅ 全仓库搜不到真实 API Key

> 以上均为 Expected Verification Steps，尚未实际执行。详见 [verification.md](verification.md)。

## 不做（Out of Scope）

- 多文档集合 / 跨文档检索
- 网页 / Office 文档解析
- Rerank 重排模型
- 公网部署与多用户
