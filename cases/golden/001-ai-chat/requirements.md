# Requirements — AI 聊天应用

> ⚠️ Verification Pending — 需求清单已就位，但功能尚未实际实现验证。

## 功能性需求（FR）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 用户能在输入框打字并点"发送"发消息 | P0 | 打字后点发送，消息出现在列表，输入框清空 |
| FR-02 | 用户能看到 AI 对消息的回复 | P0 | 发送后几秒内，回复出现在消息列表，区分用户/AI |
| FR-03 | 用户能点"清空历史"清掉所有消息 | P1 | 点击后列表清空，再发消息从空白开始 |
| FR-04 | 网络错误或 API 失败时，用户看到明确错误提示 | P0 | 断网或 key 失效时，页面显示可读错误而非白屏 |

> 术语解释：**FR（功能性需求）**= 产品"能做什么"；**P0** = 必须有，没有就不算交付。

## 非功能性需求（NFR）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| NFR-01 | 单页首次加载 < 2 秒（本地） | P1 | 浏览器打开页面到可输入 < 2s |
| NFR-02 | API Key 绝不进入前端代码或仓库 | P0 | 全仓库 grep 不到真实 key；前端代码无硬编码 key |
| NFR-03 | 请求超时要有兜底（默认 30s） | P1 | LLM 超过超时时间，页面提示"请求超时"而非无限等待 |
| NFR-04 | 回复内容做基础转义，防 XSS | P1 | 回复含 `<script>` 时作为文本显示而非执行 |

> ⚠️ NFR-01 的 "<2s" 为目标值，尚未实测。

## 验收标准（Acceptance Criteria）

端到端验收（全部通过才算交付）：

1. ✅ 本地起服务，浏览器打开能看到聊天页
2. ✅ 输入"你好"点发送，几秒内看到 AI 回复
3. ✅ 连续追问，历史消息保留可见
4. ✅ 点"清空历史"，列表清空
5. ✅ 断网再发消息，看到"请求失败"类提示（不白屏/不卡死）
6. ✅ 全仓库搜不到真实 API Key

> 以上均为 Expected Verification Steps，尚未实际执行。详见 [verification.md](verification.md)。

## 不做（Out of Scope）

- 用户登录 / 多用户
- 多会话切换
- 流式（打字机）输出
- 公网部署
