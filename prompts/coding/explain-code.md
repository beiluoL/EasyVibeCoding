# explain-code
## Use When
你看到一段代码（同事写的、开源库的、AI 生成的、自己三个月前写的），不知道它在干什么、为什么这么写。

## Goal
用大白话把一段代码讲清楚：做什么 / 怎么做 / 为什么这么做。

## Input Variables
- `{{code_snippet}}`：要解释的代码片段。
- `{{reader_level}}`（可选）：读者水平，如"完全不懂这个语言""懂 JS 不懂 Python"，影响解释深度。

## Prompt
```
你是一位会教人的资深工程师，擅长把代码用大白话讲给小白听。

【角色 Role】资深工程师 + 讲解老师
【背景 Context】用户有一段代码看不懂：{{code_snippet}}。读者水平：{{reader_level}}。需要从"做什么 / 怎么做 / 为什么这么做"三层讲清楚。
【目标 Goal】用大白话讲清楚这段代码，让读者看完能跟别人复述。
【约束 Constraints】
1. 三层讲：① 这段代码做什么（目标）② 怎么做（步骤）③ 为什么这么做（设计理由）。
2. 大白话优先，专业术语第一次出现配一句解释。
3. 不要逐行翻译代码（"这里声明变量 a"没意义），要讲意图。
4. 如果有更简单的写法，可以一句话提，但不要跑题去重构。
5. 关键行用代码注释方式标出来，让读者对得上。
【工作流 Workflow】
1. 一句话讲这段代码整体目标。
2. 按步骤讲怎么做（每步一两句，标对应行号）。
3. 讲为什么这么写（权衡、避坑）。
4. 一句话总结 + 如果有更简单写法提一下。
【输出格式 Output Format】
## 这段代码做什么
<一句话>

## 怎么做
1. <第几行> <动作>
2. <第几行> <动作>

## 为什么这么写
<设计理由 + 避免了什么坑>

## 一句话总结
<复述>
【验证 Verification】
- 是否讲了"做什么 / 怎么做 / 为什么"三层？
- 术语是否都有解释？
- 关键行是否标了行号让读者对得上？
```

## Expected Behavior
- 讲意图不逐行翻译。
- 三层结构清晰：目标 / 步骤 / 理由。
- 关键行标行号，读者能对得上代码。

## Expected Output
（示例片段）
```
## 这段代码做什么
把一个数组里重复的数字去掉，只留第一次出现的。

## 怎么做
1. 第 2 行：建一个空 Set（一种不允许重复的数据结构）。
2. 第 3 行：遍历原数组每个数。
3. 第 4 行：如果 Set 里没有这个数，加进去。

## 为什么这么写
用 Set 判重比用 includes 找数组快（Set 查找是 O(1)，数组是 O(n)），数组一大就明显。
```

## Common Mistakes
1. 逐行翻译"这里声明变量""这里是循环"，没讲意图。
2. 只讲"做什么"不讲"为什么"，读者下次还是不会写。
3. 术语堆砌不解释，小白越看越晕。
4. 顺手建议重构跑题，偏离"讲解"目标。
