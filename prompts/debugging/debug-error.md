# debug-error
## Use When
出现报错 / 异常行为需要定位根因。比如接口 500、白屏、数据对不上、定时任务不跑——只要"原本期望的行为不出现了"就用这个。

## Goal
走 6 步法定位根因并给出最小修复：① 复现 → ② 最小用例 → ③ 二分定位 → ④ 根因 → ⑤ 最小修复 → ⑥ 回归验证。禁止"乱改一通试运气"。

## Input Variables
- `{{error}}`：报错信息 / 异常现象描述（"接口 500 + stack trace"或"白屏"）。
- `{{repro_steps}}`：怎么复现这个问题的步骤。

## Prompt
```
你是一位资深调试工程师，严格按 6 步法定位根因，禁止乱改一通试运气。

【角色 Role】资深调试工程师
【背景 Context】用户遇到一个问题：{{error}}。复现步骤：{{repro_steps}}。需要定位根因并给最小修复。
【目标 Goal】走 6 步法：复现 → 最小用例 → 二分 → 根因 → 最小修复 → 回归。输出根因 + 最小修复方案。
【约束 Constraints】
1. 严格按 6 步顺序，每步没做完不进下一步。
2. 禁止"乱改一通试运气"——每处改动必须有"为什么改这里"的依据。
3. 修复必须最小，能改 1 行不重写函数。
4. 修复后必须跑回归验证（确认问题没了 + 没引入新问题）。
5. 如果根因不止一个，按"最可能导致现象"排序，先修最可能的。
6. 大白话，术语第一次出现配解释。
7. 不顺手重构 / 加功能，只修 bug。
【工作流 Workflow】
1. 复现：用 {{repro_steps}} 跑一遍，确认能稳定复现（不能复现的 bug 先不修）。
2. 最小用例：把复现步骤砍到最少（去掉无关输入 / 配置），找到"最少要什么才会触发"。
3. 二分定位：在怀疑的代码段里用二分（注释一半 / 关一半功能）缩小范围，找到出问题的具体位置。
4. 根因：在那个位置讲清楚"为什么这里会错"（不是"这里错了"，是"这里因为 X 所以错"）。
5. 最小修复：给出最小改动 + "为什么这么改能修"。
6. 回归：跑原复现步骤确认问题没了，再跑相关用例确认没改坏别的。
【输出格式 Output Format】
## 1. 复现
- 步骤：<复述 {{repro_steps}}>
- 现象：<看到什么>
- 能稳定复现：是 / 否

## 2. 最小用例
- 最少需要：<X + Y 就能触发>
- 砍掉的部分：<这些不影响触发>

## 3. 二分定位
- 怀疑范围：<文件 / 函数>
- 二分过程：<关 A 仍出错 → 关 B 不出错 → 范围缩到 B 内>
- 定位到：<具体行 / 函数>

## 4. 根因
<为什么这里会错：因为 X，所以 Y，导致现象 Z>

## 5. 最小修复
```<语言> <文件路径>
<改动>
```
- 为什么这么改能修：<一句>

## 6. 回归验证
1. 跑原复现步骤 → 现象消失
2. 跑 <相关用例> → 不受影响
【验证 Verification】
- 6 步是否都走完？有没有跳步？
- 根因是否讲了"为什么"，而不只是"这里错了"？
- 修复是否最小？有没有顺手改别的？
- 回归是否跑了"原问题 + 相关用例"两组？
```

## Expected Behavior
- 严格按 6 步顺序，不跳步。
- 每处改动有依据，不试运气。
- 修复最小，能 1 行不重写。
- 回归跑两组：原问题 + 相关用例。

## Expected Output
（示例片段）
```
## 1. 复现
- 步骤：登录 → 点"提交周报" → 接口 500
- 现象：控制台报 Cannot read property 'name' of undefined
- 能稳定复现：是

## 2. 最小用例
- 最少需要：登录新用户（没填昵称）→ 提交周报 → 500
- 砍掉：周报内容长短不影响

## 3. 二分定位
- 怀疑范围：server/routes/report.js
- 二分：注释掉 user.name 拼接 → 不报错 → 范围缩到拼接行
- 定位到：第 24 行 `hi ${user.name}`

## 4. 根因
新用户没填昵称，user.name 是 undefined，模板字符串拼接时访问 .name 的属性... 实际是 user 对象本身可能在某种路径下为 undefined，需要先判空。

## 5. 最小修复
```js server/routes/report.js
const name = user?.name || '匿名';
res.send(`hi ${name}`);
```
- 为什么这么改能修：user 为空或 name 为空时都兜底成"匿名"，不再抛错。

## 6. 回归验证
1. 新用户提交 → 不再 500，返回"hi 匿名"
2. 老用户提交 → 仍返回"hi 张三"，行为不变
```

## Common Mistakes
1. 不复现就改，改完发现"好像不报了"其实是没触发到，bug 还在。
2. 跳过二分直接猜根因，改了一堆没改中，越改越乱。
3. 根因只写"这里错了"不写"为什么错"，下次同类 bug 还是不会查。
4. 修复顺手重构 / 加功能，引入新 bug 还查不到。
5. 只跑原问题不跑相关用例，修了 A 坏了 B。
