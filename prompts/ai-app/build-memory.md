# 构建记忆（build-memory）

## Use When（何时使用）

> 想给 AI 应用加"长期记忆"：让它在跨会话间记住用户偏好、历史事实，而不是每次都从零开始。

## Goal（目标）

> 设计最小可用的长期记忆方案：存什么、怎么存、怎么检索注入、怎么过期。

## Input Variables（输入变量）

- `{{app_scenario}}`：应用场景（如：个人助理、客服、知识问答）。
- `{{memory_needs}}`：需要记什么（如：用户偏好、对话摘要、事实）。
- `{{storage_available}}`：可用存储（如：向量库、关系库、键值库）。

## Prompt（提示词正文）

```
Role: 你是一名清醒的记忆系统设计者，知道"记太多"和"记错"一样有害。
Context: 场景：{{app_scenario}}
需记内容：{{memory_needs}}
可用存储：{{storage_available}}
Goal: 给出最小可用的长期记忆方案：存什么 / 怎么存 / 怎么检索注入 / 怎么过期。
Constraints:
- 区分三类记忆并分别给方案：事实型（用户姓名等稳定信息）、偏好型（口味/习惯）、事件型（某次对话发生的事）。
- 每类说明：用什么存、检索方式（精确/向量/混合）、注入到 prompt 的方式。
- 必须给出过期与更新策略：事实变了如何覆盖、偏好如何衰减、旧事件何时归档。
- 必须给出"隐私与删除"策略：用户可删哪些、敏感信息是否落库。
- 检索结果要标注来源与时间，避免用过期记忆当现在的事实。
- 未在生产验证，标注 ⚠️ Not Yet Verified，列出需验证项（检索准确率、记忆膨胀成本、隐私合规）。
- 不编造"记忆准确率 90%"等数字。
Workflow:
1. 按三类记忆分别设计存储结构。
2. 设计写入时机（何时把什么写入记忆）。
3. 设计检索与注入 prompt 的方式。
4. 设计过期/更新/归档策略。
5. 设计删除与隐私边界。
Output format:
## 三类记忆方案
| 类型 | 存什么 | 怎么存 | 检索方式 | 注入方式 | 过期策略 |
## 写入时机
## 隐私与删除
## ⚠️ 未在生产验证的事项
Verification: 回顾是否三类记忆都有方案、是否有过期策略避免旧记忆误导、是否含隐私删除边界、是否诚实标注未验证。
```

## Expected Behavior（期望行为）

> 模型按记忆类型分别设计存取与过期，含隐私删除边界，检索结果标注来源与时间，诚实标注未验证。

## Expected Output（期望输出）

```
## 三类记忆方案
| 事实 | 用户姓名/时区 | KV库 | 精确 | 直接拼prompt | 用户修改即覆盖 |
| 偏好 | 喜好 | 向量库 | 向量 | top3 注入 | 30天未出现衰减 |
| 事件 | 对话摘要 | 向量库 | 混合 | 相关3条 | 90天归档 |
## 隐私与删除
用户可一键删除全部记忆；敏感字段不入库
## ⚠️ 未在生产验证
检索召回、记忆膨胀成本、合规均未实测
```

## Validation（验证）

- 事实/偏好/事件三类记忆都有存取方案。
- 有过期策略，避免旧记忆被当现在事实。
- 含隐私与删除边界。

## Common Mistakes（常见错误）

- 把所有东西都塞进记忆不分类，检索又慢又乱、过期无从下手。
- 只管写入不管过期，旧偏好永远覆盖新事实，越用越错。
- 不设计删除边界，用户隐私数据落库无法清理，合规出事。
- 编造记忆准确率数字。
