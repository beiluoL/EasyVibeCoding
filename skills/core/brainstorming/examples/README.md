# 示例：笔记存储方案对比

## 输入（待决策问题）

笔记网站的数据存在哪？MVP 只给个人用，暂不考虑多端同步。

## 对比表

| 方案 | 优点 | 缺点 | 风险 |
|------|------|------|------|
| localStorage | 零依赖、上手快、浏览器原生 | 容量约 5MB、不能跨设备、清缓存就丢 | 数据量一大就爆，无备份 |
| SQLite（本地/服务端） | 结构化查询、容量大、可靠 | 要后端、部署复杂度上升 | MVP 阶段过重 |
| 云数据库（如 Supabase） | 可扩展、多端同步、有备份 | 要联网、要配鉴权、有学习成本 | 个人用 MVP 用不上同步 |

## 选定

**localStorage** —— 理由：MVP 只给个人本地用、零依赖、半天能跑通，符合"小步快跑"。
（若后续走前后端分离架构，则选 SQLite。）

## 否决方案

- SQLite：MVP 阶段引入后端得不偿失，留待 P1 多端需求再升级。
- 云数据库：个人单机用不上同步与备份，鉴权成本高。

## 要点

- 3 个方案都列了
- 选定理由绑定"MVP + 个人用"约束
- 否决方案保留了原因
