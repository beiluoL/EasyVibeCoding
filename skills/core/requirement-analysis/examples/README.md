# 示例：笔记网站需求清单

## 输入（Project Brief 摘要）

极简笔记网：让普通人能新建/编辑/删除笔记并持久化。MVP 不做登录、分享、富文本。

## 输出（需求清单）

| 编号 | 类型 | 需求描述 | 优先级 | 验收标准 |
|------|------|----------|--------|----------|
| FR-01 | 功能 | 用户能新建一条笔记（标题 + 正文） | P0 | 点击新建后出现空笔记，填写后可保存 |
| FR-02 | 功能 | 用户能编辑已有笔记 | P0 | 打开旧笔记修改内容，保存后内容更新 |
| FR-03 | 功能 | 用户能删除笔记 | P0 | 删除后列表中消失且刷新不复现 |
| FR-04 | 功能 | 用户能在列表中看到所有笔记 | P0 | 进入首页展示全部笔记标题 + 时间 |
| FR-05 | 功能 | 刷新页面笔记还在（持久化） | P0 | 关闭浏览器重开，数据不丢 |
| NFR-01 | 非功能 | 首页打开 < 1 秒 | P1 | 本地环境下首屏渲染 < 1s |
| NFR-02 | 非功能 | 数据在浏览器关闭后仍保留 | P0 | 重启浏览器数据不丢 |
| NFR-03 | 非功能 | 在 Chrome/Edge 最新版可用 | P1 | 两个浏览器核心功能正常 |

## 要点

- FR 用"用户能做 X"
- 每条验收标准可一句话检验
- 持久化既是 FR（FR-05）也是 NFR（NFR-02），从不同角度描述——这是允许的
