# Systematic Debugging — 系统化排障

> 定位 Bug 不靠猜：复现 → 最小用例 → 二分定位 → 根因 → 最小修复 → 回归验证。

## 一句话

先能稳定复现，再一步步收窄到根因，修最小一处，最后确认没改坏别的地方。

## 核心原则

- **修复前先复现**：不能复现就没法验证是否修好。
- **找根因，不只消表象**：报错信息不是根因，"为什么会这样"才是。
- **修复后必须回归验证**。

## 术语

- **根因**：真正导致 Bug 的原因，不是报错本身。例：报错是"列表为空"，根因可能是"查询条件多写了一个过滤"。
- **二分定位**：把代码砍一半看还错不错，快速缩小范围。

## 6 步工作流

1. 稳定复现（找到必现步骤）
2. 缩到最小用例
3. 二分定位嫌疑代码
4. 找根因（不是表象）
5. 最小修复（只改一处）
6. 回归验证（原用例 + 相关测试）

## 反模式

- AI 无限改 Bug 循环
- 改一堆地方碰运气
- 只消掉报错不找根因
- 修完不跑回归

## 产出格式

```
Bug 现象：<>
复现步骤：<最小用例>
定位过程：<二分路径>
根因：<为什么>
修复改动：<哪一处>
回归验证：<原用例 + 测试>
```
