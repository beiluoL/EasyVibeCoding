# Code Review — 结构化代码评审

> 用清单逐项评审 AI 生成代码：正确性 / 安全 / 可维护 / 可读，而不是"看起来没问题"。

## 一句话

按清单逐项过，标问题等级，每条给位置+理由+建议，blocker 不修不放行。

## 评审清单（每项必过）

**正确性**
- 是否满足验收标准
- 是否有未处理错误（空值、异常、失败分支）

**安全**
- 是否有硬编码密钥/密码/路径
- 是否有 SQL 注入风险（拼接而非参数化）
- 是否有 XSS 风险（未转义直接输出）

**可维护**
- 是否有重复代码
- 是否过度设计

**可读**
- 命名是否清楚
- 逻辑是否直观

**测试**
- 关键路径是否需要补测试

## 问题等级

| 等级 | 含义 | 是否阻塞 |
|------|------|----------|
| blocker | 安全漏洞/逻辑错误/会崩溃 | 必须修，不放行 |
| warn | 有隐患，能跑但不健壮 | 建议修，不阻塞 |
| nit | 锦上添花 | 可选 |

## 4 步工作流

1. 对清单逐项过
2. 标问题等级（blocker/warn/nit）
3. 每条给位置+理由+建议
4. 区分"必须改"与"可选"

## 反模式

- "代码没问题"式评审
- 只看格式不看逻辑
- 忘记查安全
- 只说"有问题"不说怎么改

## 产出格式

```
评审对象：<文件/功能>
清单结果：逐项 ✅/❌
问题列表：[等级] 位置 — 理由 → 建议
结论：blocker 全清可放行 / 仍有 blocker 待修
```
