# Testing — 最小可验证测试

> 给功能写最小测试，让"做完"有客观标准，而不是靠人感觉。

## 一句话

从验收标准挑可测点，写正常+边界+错误三类测试，跑通才算完。

## 术语

- **先红后绿**：先写会失败的测试，再写代码让它通过。一开始就绿说明没在测东西。
- **边界**：极端输入（空值、超长、特殊字符），Bug 高发区。
- **回归测试**：修完 Bug 后跑的测试，确认没改坏原来的。

## 4 步工作流

1. 从验收标准挑可测点（输入 X → 期望 Y）
2. 写最小测试，先红后绿
3. 覆盖正常 + 边界 + 错误路径
4. 跑通 = 完成的客观证据

## 核心原则

- 不追求 100% 覆盖率，追求关键路径有测试
- 测试要快、独立、可重复
- 一个测试只测一件事

## 反模式

- 不写测试只靠手动点
- 测试依赖顺序
- 写一堆慢测试
- 只测正常路径

## 产出格式

```
功能：<名称>
可测点：<挑出的>
测试用例：
  - 正常：<输入 → 期望>
  - 边界：<输入 → 期望>
  - 错误：<输入 → 期望>
结果：✅/❌
```
