# Implementation — 小步实现

> 让 AI 写出能真正运行的代码，而不是看起来对、一跑就崩的代码。

## 一句话

一次只做一个任务，给够上下文，要求只改这一步，跑通了再进下一步。

## 核心原则

- **一次一个任务**：从任务清单取一个，做完再取下一个。
- **复用优先**（Reuse before reinvent）：项目已有的库、函数、模式，直接用，别让 AI 重造。
- **只改该改的**：不允许 AI 顺手重写无关代码。

## 适用场景

- 功能已拆成单步任务，准备动手编码。
- 需要把一个需求落地成可运行代码。

## 前置条件

- 已有 task-planning 产出的任务清单。
- 当前任务的验收点已定义。
- 项目结构、相关文件路径已知。

## 工作流（5 步）

1. 取单个任务
2. 给 AI 明确上下文（项目结构 + 相关文件 + 已有模式）
3. 要求只改这一步
4. 跑起来看结果
5. 过验收点 → 进下一步；没过 → 停下来修

## 反模式

- 一个 prompt 写完整个项目
- AI 自行改无关文件
- 不验证就堆功能
- 重新造已有的轮子

## 产出格式

```
任务：<标题>
改动文件：<路径列表>
改动说明：<一两句>
验证方式：<跑了什么>
验收点：<✅/❌ 逐条>
```
