# Context Engineering 上下文工程

## 是什么

Context Engineering（上下文工程）是决定"此刻 AI 该看到哪些信息"的活儿。大白话：AI 的"工作记忆"就那么大，你得挑最相关的几样东西放进它眼前，而不是把整个项目倒给它。

AI 没有长效记忆，它只能基于你这次给它的内容来回答。给多了它抓不住重点甚至超出长度上限，给少了它就靠猜。Context Engineering 就是这门"取舍"的功夫。

## 为什么重要

- **AI 看不到你没给的东西**：你的项目、你的约定、你刚才的决策，AI 默认一无所知。
- **上下文窗口有限**：再大的模型也有容量上限，塞满整个仓库既慢又贵还容易丢重点。
- **给错上下文 = 给错答案的根源**：很多"AI 蠢"其实是"我们没给它该看的"。

这门能力直接决定 Prompt、Skill、Agent 的产出质量。

## 什么时候用

- 每次 AI 给的答案"明显不知道项目情况"时，先检查上下文，而不是反复改 Prompt 措辞
- 任务涉及多个文件、需要保持一致性时
- 用 Agent 跑长任务，需要决定它每次能读什么、记住什么

## 怎么用

挑上下文就像给同事交接一个活，按"够用且不超载"原则取舍：

| 该给 | 不该给 |
| --- | --- |
| 当前要改的文件 | 整个项目所有文件 |
| 相关的接口定义、数据模型 | 无关模块的实现细节 |
| 项目约定（命名、分层、规范） | 过时的旧文档 |
| 这次任务的明确目标和约束 | 历次所有对话记录 |
| 一两个相似实现作参考 | 网上抄来的不相关代码 |

实操步骤：

1. 先问自己：AI 完成这步最少需要知道什么？
2. 只把这些贴进上下文或让它读对应文件
3. 让 AI 先复述它理解到的目标和约束，确认没跑偏
4. 发现它漏了关键信息，再针对性补，别一股脑全倒

相关技能见 [`skills/ai/context-engineering`](../../skills/ai/context-engineering)。

## 常见误用

- **把整个项目丢给 AI "你自己看"**：超窗口、慢、贵、丢重点，AI 还可能引用到过时部分。
- **只贴代码不给目标和约束**：AI 不知道你要干嘛，只能"看起来像在改代码"。
- **一次塞太多对话历史**：早期无关内容会稀释当前任务的注意力。
- **不验证 AI 的理解**：AI 可能自以为懂了。让它复述目标和约束能低成本纠偏。
