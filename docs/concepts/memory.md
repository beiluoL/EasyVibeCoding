# Memory 记忆

## 是什么

Memory（记忆）是让 AI 跨会话记住信息的能力。大白话：普通对话关掉就忘，Memory 是给 AI 装一个"笔记本"，下次开新对话还能翻出来看。

默认情况下，AI 是"金鱼记忆"——每个新会话从零开始，上次聊过什么它一概不知。Memory 就是用来打破这个限制的。

## 为什么重要

- **不重复交代背景**：项目架构、个人偏好、技术栈选型，记一次下次就能用。
- **保持长任务一致性**：跨多次对话改同一个项目，决策不会前后打架。
- **沉淀经验**：原则 06 Every mistake becomes knowledge——踩过的坑记下来，下次绕开。

但 Memory 也是双刃剑：记错或记过时信息，反而会持续误导 AI。

## 什么时候用

- 项目级长期事实：技术栈、目录结构、命名约定
- 个人偏好：代码风格、注释语言、提交信息格式
- 踩坑记录：某个第三方库的坑、某条命令的注意事项
- 跨会话的长任务：分多次推进的目标

## 怎么用

把 Memory 当作分层的笔记本：

| 层级 | 记什么 | 例子 |
| --- | --- | --- |
| 项目级 | 整个项目都成立的事实 | "后端用 Spring Boot 3 + MyBatis-Plus，前端 Vue3 + Vite" |
| 个人级 | 你的偏好 | "提交信息用中文，代码注释用英文" |
| 任务级 | 当前长任务的进度 | "订单重构已完成第 2 步，待做第 3 步接口联调" |
| 教训级 | 踩过的坑 | "X 库 1.2 版本有内存泄漏，必须用 1.3+" |

实操要点：

1. 只记"以后还会用到"的，临时信息别进 Memory
2. 记下的内容要可验证、有日期，避免记成"感觉"
3. 项目变了要同步更新，过时记忆比没有记忆更糟
4. 敏感信息（密钥、密码、内部数据）绝不进 Memory

相关技能见 [`skills/ai/memory`](../../skills/ai/memory)。

## 常见误用

- **什么都往 Memory 塞**：变成垃圾堆，AI 反而找不到有用的。只记可复用的结论。
- **记"感觉"不记事实**：比如记"这个库不好用"不如记"这个库在并发场景下会丢数据"。
- **不更新导致过时**：技术栈换了、约定改了，旧 Memory 会持续误导。
- **把密钥/隐私写进 Memory**：违反安全原则，记忆可能被多处引用。
- **以为有 Memory 就不用给上下文**：Memory 是补充不是替代，每次仍需给当前任务的相关上下文（见 [context-engineering](./context-engineering.md)）。
