# 01 — 什么是 Vibe Coding

> 你完全不会编程？太好了，这篇就是写给你的。

> 术语小贴士：**Vibe Coding**（凭感觉编程）= 你不写代码，用自然语言描述需求，让 AI 生成可运行的代码。

---

## 用大白话说：Vibe Coding 是什么

想象你去餐厅吃饭：

| 传统写代码 | Vibe Coding |
| --- | --- |
| 你自己进厨房炒菜（切菜、调火、下锅、调味） | 你点菜（告诉厨师要什么口味、什么食材），厨师（AI）炒给你 |
| 你得会刀工、懂火候 | 你得会说清楚要什么、会判断菜对不对 |
| 门槛在"会炒菜" | 门槛在"会点菜 + 会验收" |

**Vibe Coding 就是：你当"点菜的人"，AI 当"厨师"。你不写代码，你描述需求、判断结果、一步步让 AI 把软件做出来。**

---

## 它和"AI 写代码"有什么区别

很多人以为 Vibe Coding = "一句话让 AI 写整个项目"。**这是最大的误解**。

| | 让 AI 直接写整个项目 | Vibe Coding（工程化） |
| --- | --- | --- |
| 怎么做 | "帮我写个淘宝" | 拆成需求 → 设计 → 实现 → 测试 → 验证，一步步来 |
| 结果 | 大概率跑不通，且改不动 | 一步步能跑、能测、能维护 |
| 出错怎么办 | 重新生成，碰运气 | 系统化调试，定位修复 |
| 代码可信吗 | 不可信 | 每步有验证，可信 |

一句话区别：**Vibe Coding 是"有章法地指挥 AI"，不是"甩一句话碰运气"。**

---

## 为什么"工程化"很重要

很多人用 AI 写代码的真实状态是：

> 一句话生成 → 跑不通 → 再问一句 → 又跑不通 → 改了又改 → 放弃。

问题不在 AI，而在**缺少工程化方法**。EasyVibeCoding 的 7 条原则里，有两条最关键：

### Principle 02 — Small tasks over giant prompts（拆小任务，别一句话塞太多）

**大白话**：别让 AI 一次干太多。一次做一小块，做完验证，再做下一块。

为什么？AI 的"记忆"有限，一次塞太多需求，它会忘掉前面的；而且一旦出错，你不知道是哪一步出的。小步走，错了早发现。

### Principle 07 — From Prompt to Production（从提示词到能上线的软件）

**大白话**：目标不是"AI 生成了代码"，而是"做出了能真正运行的软件"。

生成代码只是第一步，后面还有测试、调试、验证、部署——这些都是工程化要解决的。

## Vibe Coding 适合谁

| 人群 | 适合吗 | 你能拿到什么 |
| --- | --- | --- |
| 🐣 完全不会编程 | ✅ 很适合 | 跟着路线，用 AI 做出真正能跑的软件 |
| 🎯 产品经理 | ✅ 适合 | 用工程化方式把需求拆给 AI，减少返工 |
| 🛠 独立开发者 | ✅ 适合 | 复用 Skill / Prompt，加速单人交付 |
| 🤖 想学 AI 工程的人 | ✅ 适合 | 系统理解 Prompt→Skill→Workflow 全链路 |

不适合谁？
- 想"完全不学习、躺着让 AI 做完一切"的人——Vibe Coding 仍需要你动脑、做决策、验证结果。
